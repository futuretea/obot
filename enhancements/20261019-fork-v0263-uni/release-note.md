# fork/v0.26.3-uni 发布说明

这份说明留在仓库里，不发 GitHub Release，不发到仓库外。

## 你会看到的变化

- 页面上的产品名从 “Obot” 变成 “uni”。浏览器标题、按钮和提示都按这个名字显示。
- 登录仍走 Keycloak。登录成功后回到应用，并显示已登录状态。
- 用户数和设备数不再被 100 的上限拦住。

## 这一版不再提供

- 单会话。新登录不会把同一账号的旧登录挤掉，多个登录可以同时留着。
- 0.20 一代的 `obot-tools`。这一版只使用 `obot-providers`。

## 升级后用户得到的

- 已有 MCP Server 会变成虚拟 MCP。一个地址可以带上多个服务，访问范围和凭据仍按原来的配置带过去，旧连接地址不用改。
- 可以建 MCP 隧道，让应用连到它本来访问不到的内网 MCP Server。
- 可以查看并导出 LLM 调用审计；模型供应商新增 AWS Bedrock、Azure 和通用接口。
- 设备侧可以登记设备、下载 MDM 配置，并记录工具调用是否被允许。
- 需要时可以打开新的 Agent。它单独运行一个容器，能把工作流和定时任务通过 MCP 提供给其他客户端。
- 用户数和设备数不再被 100 的上限拦住。已有 API key 继续可用。

## 上游从 v0.20.1 到 v0.26.3 带来的变化

- v0.22 起不再提供旧的项目聊天、助手、分享和任务。0.20 的 Agent、项目和任务不会自动搬进新版本。旧 Agent 上的定时任务也不再触发，不会被搬进新的 nanobot 定时任务。
- v0.23 起旧认证 token 弃用，API token 范围有变化；模型与认证组件改在容器里运行。
- v0.24 起可以在应用内做本地登录，并查看、导出 LLM 审计；模型供应商增加 AWS Bedrock、Azure 和通用接口。
- v0.25 起原来的 API key 改为 Agent Auth Scope，并增加用户数、设备数限制和 MCP 隧道。
- v0.26 起启动时会把已有 MCP Server 转成虚拟 MCP，配置和凭据带过去，然后删除旧记录。旧连接地址仍可使用。新的 Agent 会起一个独立的 nanobot 容器，并通过 MCP 提供服务；它不承接 0.20 的旧 Agent。该功能默认关闭，需要时设置 `OBOT_ENABLE_AGENTS=true`。

## 数据库

- 数据库仍用原来的 Postgres，但启动迁移会删除旧聊天运行记录、线程、会话和一批旧 token 表。用户创建的 API key 会保留。旧 Agent 与定时任务的记录还在库里，只是不再被读取。升级前备份整个库。

## 地址和配置不变

登录地址、环境变量、接口字段和代码标识保持原名。只改了界面上能看见的产品名。
